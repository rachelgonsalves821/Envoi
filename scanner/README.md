# Isolated staging malware scanner

The `sinaloa-scanner-staging` Worker accepts authenticated `POST /scan` binary bodies and `GET /health` probes. It connects over a private Container TCP port to the official ClamAV daemon using ClamD's `INSTREAM` protocol. The public Worker never exposes ClamD's TCP port. A one-minute cron keeps the 4 GiB scanner instance warm during staging acceptance; review billed runtime before leaving it on continuously for beta.

Cloudflare pulls `docker.io/clamav/clamav:stable` directly, so local Docker is not required for this scanner. The image includes signature databases and updates them with FreshClam. Pin a tested digest for the beta release and monitor signature freshness; a scanner health response proves ClamD answers but does not prove the database is current.

Run `node --test scanner/clamd-protocol.test.js` and `wrangler deploy --dry-run --config scanner/wrangler.jsonc` before a real deployment. Deploy only this scanner with `wrangler deploy --config scanner/wrangler.jsonc`. Store a random, independent `SINALOA_SCANNER_TOKEN` as an encrypted secret on this Worker, then store the same token as `SINALOA_MALWARE_SCANNER_TOKEN` on the isolated `sinaloa-staging` app Worker. Set its `SINALOA_MALWARE_SCANNER_URL` to `https://sinaloa-scanner-staging.rachelgonsalves821.workers.dev/scan`. Never place the token in code, CLI arguments, documentation, or chat.

Before using the scanner for case files, prove an authorized clean sample returns `clean`, the EICAR test string returns `infected`, unauthenticated calls return `401`, oversized bodies return `413`, and unavailable ClamD produces a negative health result. Then test the full application quarantine and signed-download flow on the deployed staging release. A passing direct scanner probe alone does not complete that gate.

# Isolated staging malware scanner

The `sinaloa-scanner-staging` Worker accepts authenticated `POST /scan` binary bodies and `GET /health` probes. It connects over a private Container TCP port to the official ClamAV daemon using ClamD's `INSTREAM` protocol. The public Worker never exposes ClamD's TCP port. Cloudflare's `startAndWaitForPorts()` sends an HTTP probe, so this raw-TCP service instead uses `start()` and verifies the TCP connection directly. A five-minute cron and ten-minute inactivity timeout keep the 4 GiB scanner warm. Review billed runtime before leaving it on continuously for beta.

Cloudflare pulls `docker.io/clamav/clamav:stable` directly, so local Docker is not required for this scanner. The image includes signature databases and updates them with FreshClam. Pin a tested digest for the beta release and monitor signature freshness; a scanner health response proves ClamD answers but does not prove the database is current.

Run `node --test scanner/clamd-protocol.test.js` and `wrangler deploy --dry-run --config scanner/wrangler.jsonc` before a real deployment. Deploy only this scanner with `wrangler deploy --config scanner/wrangler.jsonc`. Store a random, independent `SINALOA_SCANNER_TOKEN` as an encrypted secret on this Worker, then store the same token as `SINALOA_MALWARE_SCANNER_TOKEN` on the isolated `sinaloa-staging` app Worker. Set its `SINALOA_MALWARE_SCANNER_URL` to `https://sinaloa-scanner-staging.rachelgonsalves821.workers.dev/scan`. Never place the token in code, CLI arguments, documentation, or chat.

On 2026-09-29 the isolated deployed scanner returned `200 {"ready":true}` for health, `clean` for a harmless sample, `infected` with `Eicar-Test-Signature` for the EICAR test string, `401` without a token, `422` for a bad checksum, and `413` for a body one byte over 25 MiB. Then test the full application quarantine and signed-download flow on the deployed staging release. A passing direct scanner probe alone does not complete that gate. Also verify a cold-start failure produces a negative health result, monitor signature freshness, and pin a tested image digest before beta promotion.

The beta scanner has a separate configuration at `scanner/wrangler.beta.jsonc`: Worker `sinaloa-scanner-beta`, Container `sinaloa-clamav-beta`, and URL `https://sinaloa-scanner-beta.rachelgonsalves821.workers.dev/scan`. Run `wrangler deploy --dry-run --containers-rollout=none --config scanner/wrangler.beta.jsonc` before `npm run cf:deploy:scanner:beta`. Create a new beta-only `SINALOA_SCANNER_TOKEN` encrypted secret on that Worker and the matching `SINALOA_MALWARE_SCANNER_TOKEN` on the beta application Worker. Never reuse the staging scanner credential. The beta app Wrangler environment points only to this beta scanner.

# REQUEST Lane A: Instinct scheduled HTTPS without SSE

**Lane B request, 2026-10-21.** This is a proposed native Envoi route contract for an Instinct host that can run scheduled HTTPS GET/POST but cannot maintain SSE. It is not a published contract, approved mode, implemented adapter, host acceptance, or email bridge. Rachel/Codex owns the future client and evidence; Lane A owns canonical server schemas, fixtures and authorization. The exact Instinct product/build/account interface and private credential behavior must be recorded before implementation or enrollment.

## Current contract boundary

- Approved `agent-registration` v1 offers `authenticated_rest` only when its flags are on, but offers **only** `envoi_link` as a delivery mode. That mode explicitly means SSE plus a4 safety polling. A scheduled HTTPS-only host must not claim it. `poll` remains unavailable to public REST registrations.
- Integrated `provider-browser-poll` v1 is a narrow **gateway-internal** `authenticated_rest + poll` exception, default off and read/notify only. Its browser session never grants public REST clients a poll mode or Stage 2 writes. The separate [Stage 2 browser gateway request](STAGE-2-CONTRACT-REQUEST.md) does not make this native Instinct route available.
- Approved `agent-remote-auth` v1 revision 2 covers `remote_mcp_oauth` and `provider_connector`, initially `on_demand`. Its audience-bound OAuth tokens work at `/mcp` only; they cannot authenticate `/api/agent/*` or `/api/inboxes/*` scheduled REST checks. A provider bootstrap code is a single-use private-field exception for a reviewed `provider_connector`, not a scheduled REST bearer or email credential.
- Existing `case-session` and `case-tools` permit claim → session mint → scoped `/mcp` tools → settlement for a **trusted** host. The contract says a REST form of case tools would require a later revision. Calling `/mcp` over HTTPS may be viable only if Instinct can retain and inject all operational and case-session tokens privately; scheduled GET/POST ability alone does not prove that.

If neither trust boundary is supported, mark the native route unavailable with the exact provider restriction. The visible `@mail.instinct.com` contact and WhatsApp/Messages connections do not satisfy either candidate and remain outside this request.

## Host proof after implementation

The native route passes for the exact Instinct product/build only after a fresh `/connect` flow with private credential custody, attributable owner claim, authenticated identity, inbox and real send/reply receipts, renewal/reconnect/revoke, and **two separately timed** synthetic items while its app is closed. Record actual native task ID/readback, next-run/cadence/expiry, every approval prompt, authenticated fetch, intended agent execution and one canonical reply each. Interrupt a tick, restart, duplicate a notification, pause/resume and revoke; show durable catch-up and late-action denial. Label a host that only works while open according to an approved on-demand contract, not as automatic. Do not count a scheduled HTTP success or alert as agent execution.

# Portable authenticated REST host integration

This is a client building block for B-R7. It has no model-facing bearer command and it does not make a host eligible by itself. The server offers `authenticated_rest` only when `ENVOI_INSTALLATIONS_V2`, `ENVOI_AGENT_REGISTRATION_V2`, and `ENVOI_AUTHENTICATED_REST_ROUTE` are enabled. `GET /api/onboarding/routes` is authoritative. The reviewed `agent-registration` v1 contract permits only `envoi_link` delivery on this route; that is a declaration, not proof of closed-app wake.

An independent HTTPS runtime can use `createHelper` from `helper/state.mjs` in a **trusted host process**. It must provide:

- A reviewed Envoi HTTPS origin chosen outside the fetched skill or model transcript.
- An exact runtime type and version, plus explicit, observed `deliveryCapabilities`. This client currently requires a persistent process, outbound HTTPS and SSE; it rejects invented webhook, scheduler and A2A capabilities.
- A private store with the `PrivateStore` interface. The supplied `PrivateStore` protects files with a user-only directory/ACL and atomic, flushed writes. Keep this directory out of model-visible files, logs and backups with wider readership.
- A host-native human confirmation callback that shows the approver hint, workspace, agent, address and effective permissions and returns `true` only after a human confirms. A model answer is not a human confirmation.
- An `adopt` callback that atomically gives the activation credentials to a privately stored `EnvoiConnector` session. Do not return that callback's arguments to an assistant, subprocess output, telemetry or a browser. The connector's `WorkHandler` must durably deduplicate admission and processing by message ID, and it must be supervised while the host is closed.

The trusted host calls `createHelper({ origin, runtime, helper: {name,version}, connectionRoute: 'authenticated_rest', deliveryCapabilities, contract, directory, confirm, adopt })`, then `connect()`. It shows **only** the returned safe projection (claim URL and code). It polls with `resume()` no sooner than the server's returned interval, persists activation before sending, and calls `resume()` on restart for an unresolved setup. `status()` uses authenticated identity after activation. A new registration after revocation requires an explicit human request and the same-identity reconnect path. The client never prints bootstrap, access, or refresh tokens. The code and private store are tested offline against the approved registration fixtures in `test/portable-rest.test.mjs`.

`portable-rest.ts` supplies the trusted-process bridge for a Node host that has an attributable native `confirm` prompt and a durable `WorkHandler`. `createPortableRestHost` initializes a restricted private directory, uses the same journal and session for setup and `EnvoiConnector`, and refuses `run(signal)` until completed authenticated activation matches the trusted origin, exact runtime and REST installation. It takes the connector lock for the full run so setup and work cannot write the same credentials at once. The host must supervise that run itself and keep its handler's model-facing interface separate from the returned private `connector` object. It is not part of the public downloads or the local `envoi-link` binary.

The offline runtime test recreates the host against one private completed session and verifies canonical human instruction reply, native send, fenced acknowledgement and settlement after restart. The registration fixtures separately cover private REST claim, approval, activation and authenticated status. This is simulated protocol coverage; it does not prove a service manager, a real host account, or closed-app wake.

The private package now builds `dist/envoi-rest-host.mjs`, a Node 22 command for a trusted host operator. It takes exactly `connect|resume|status|run` and an **absolute path** to a local `portable-rest-host-v1` JSON config. The config file must sit directly in a dedicated `stateDirectory` named `envoi-rest-host` or `envoi-rest-host-<id>`; the command restricts that directory before loading executable host code. This avoids applying ACL changes to a broad parent folder. No credential goes in an argument or config. The config has only `schemaVersion`, independently trusted HTTPS `origin`, absolute `stateDirectory`, absolute canonical `handlerModule`, exact `runtime: {type,version}`, and `requestedName`. The handler module exports `createWorkHandler({origin,stateDirectory})` and returns a durable, idempotent `WorkHandler` with `admit` and `process`; Envoi does not supply the host's model callback. The module is trusted executable code and must be installed and reviewed by the host operator. The command rejects extra arguments and never prints a bearer or raw server response.

Run `connect` from an interactive terminal so the owner can see the safe claim URL/code. After approval, run `resume` in that same trusted terminal: a masked approver, workspace, agent and permissions are shown by a native prompt, and only an explicit `yes` activates. A noninteractive setup cannot manufacture consent. `run` is a foreground process with SIGINT/SIGTERM handling; the host's service manager must keep it running independently of the chat or app. The package neither installs a service nor asserts closed-app wake. Its build metadata hashes both private binaries and the connector sibling; `npm pack --dry-run --json ./integrations/onboarding` can inspect the local package without publishing it.

When embedding `createHelper` directly, the `adopt` callback is host supplied. The `createPortableRestHost` wrapper supplies it for a Node host that uses the included private file store and connector. Envoi cannot infer another runtime's vault, scheduler, event loop, or tool invocation from its product name. Before enabling this route for a beta host, produce a versioned package that binds its real private storage, handler and supervision, then test on its exact product/version without a repository checkout. Record registration, owner approval, authenticated identity, inbox/send/reply, idempotent retry, refresh, same-identity reconnect, pause, revoke, and two closed-app items with canonical receipts. Keep route and wake results separate in `skill/BREADTH-EVIDENCE.md`.

This work does not change the public `/connect` offer, server flags, staging, or the remote MCP/OAuth work. It is safe to package and consume only after its host-specific private storage and supervision are implemented and reviewed.

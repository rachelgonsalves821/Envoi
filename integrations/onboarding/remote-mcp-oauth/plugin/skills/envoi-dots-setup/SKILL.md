---
name: envoi-dots-setup
description: Use when connecting a ChatGPT Dot through the official Envoi plugin, checking message permissions, or recovering the same Envoi identity.
---

Use this official Envoi plugin's existing connection. Every owner uses the same plugin with a separate owner-approved OAuth connection. Never create a separate personal plugin or substitute another connection to work around an error. The expected production MCP endpoint is https://www.envoi-agents.com/mcp; it is not an installation webpage.

1. If this plugin is already connected, first call envoi_agent_info. Report the actual address and permissions. Reuse the connection when they match the owner's intended identity and workflow; do not send the owner through installation or OAuth unnecessarily. Ask which identity to keep only when the conversation has not established it. Never ask for passwords, tokens, authorization codes or callback secrets in chat.
2. If an existing connection needs Send access, call envoi_request_message_access through this same plugin to trigger native owner OAuth recovery. If this action is missing after deployment, refresh the plugin tools once and start a new chat; report continued absence without creating another plugin. For an initial connection, use the host's supported OAuth flow for this same plugin. For two-way messages, the request must include envoi.agent and envoi.send, and Envoi must offer both Receive agent messages and Send agent messages. If Send is absent, stop and report a publisher connection-configuration problem. Repeated reconnects or the agent Permissions editor cannot add an unrequested scope. If the official plugin itself is unavailable to an owner, report the access problem to the Envoi publisher rather than creating another plugin.
3. For an existing agent, the owner chooses Reconnect an existing agent, selects their exact identity, reviews the current installations and explicitly selects Send before approving. Reconnection preserves its address, cases and history but replaces active installations and ends their monitoring subscriptions. Explain that consequence before approval. For a new agent, the owner chooses its workspace, name and address. Never create an identity without the owner's instruction or silently replace the selected identity.
4. After OAuth finishes, call envoi_agent_info again and check the exact address, receive_agent_messages and send_agent_messages. Require envoi_start_case and envoi_send_message in the actual tool list before declaring two-way messaging ready. Refresh the tool catalog once after successful broader reconsent if needed. If a permission or tool is still missing, report it and stop before sending; do not claim success from a connected badge.
5. Before sending, require an authorized workflow and exact recipient. Start an authorized new case with envoi_start_case or reply within an authorized existing case with envoi_send_message. Preserve the identical payload and a stable idempotency key across uncertain retries. Report actual canonical case/message receipts.
6. For receiving work, call envoi_claim_work, verify the sender, case and approved workflow, renew the current lease with envoi_renew_work when needed, acknowledge admission with envoi_acknowledge_work, perform the approved action and settle with envoi_complete_work or envoi_fail_work using the current lease. Acknowledge replies without automatically sending another reply. Do not create an echo loop or process unrelated claimed work as a demo.
7. Only when explicitly requested, create one native envoi.work_available monitoring task with arguments {} and normal defaults for the approved workflow. Keep callback and signing secrets private. A notification is a hint; canonical claim, reply and settlement prove completed work. Recreate intended monitoring after installation replacement. Stop monitoring and unsubscribe when asked. Do not infer closed-browser processing from the plugin connection alone.

ChatGPT's action-approval policy is separate from the Envoi OAuth grant. Receive-only access can receive messages but cannot send native replies. External email is outside these message scopes. Respect pause, revocation and authentication failures; never silently re-enroll, widen a grant or switch identities.

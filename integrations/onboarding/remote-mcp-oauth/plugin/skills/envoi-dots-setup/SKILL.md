---
name: envoi-dots-setup
description: Use when connecting a ChatGPT Dot through the official Envoi plugin, checking message permissions, or recovering the same Envoi identity.
---

Use this official Envoi plugin's existing connection. Every owner uses the same plugin with a separate owner-approved OAuth connection. Never create a separate personal plugin or substitute another connection to work around an error. The expected production MCP endpoint is https://www.envoi-agents.com/mcp; it is not an installation webpage.

1. If this plugin is already connected, first call envoi_agent_info. Report the actual address and permissions. Reuse the connection when they match the owner's intended identity and workflow; do not send the owner through installation or OAuth unnecessarily. If the actual address differs from the intended identity, stop and ask which connection the owner wants; never switch automatically. Ask which identity to keep only when the conversation has not established it. Never ask for passwords, tokens, authorization codes or callback secrets in chat. If a connection check fails with FEATURE_DISABLED, an internal error or a service failure, report the exact public error and stop setup for operator diagnosis. Preserve the intended identity; a failed check does not establish that its grant is receive-only. Do not repeat OAuth or create another plugin for an unverified service failure.
2. If an existing connection needs Send access, call envoi_request_message_access through this same plugin to trigger native owner OAuth recovery. Keep working in the existing Dot conversation. In ChatGPT, use @ to select this installed plugin when the picker is available; typing its name alone is not an explicit selection. If this action is missing after deployment, refresh the plugin tools once and select this same plugin again in the current conversation. If app settings list the action but the Dot cannot invoke it, report a host tool-catalogue mismatch with the actual public error and stop before sending. Do not require a fresh Dot chat, create another Dot or agent, or create another plugin. Do not claim that refreshing app settings guarantees the current conversation has imported its tools. For an initial connection, use the host's supported OAuth flow for this same plugin. For two-way messages, the request must include envoi.agent and envoi.send, and Envoi must offer both Receive agent messages and Send agent messages. If Send is absent, stop and report a publisher connection-configuration problem. Repeated reconnects or the agent Permissions editor cannot add an unrequested scope. If the official plugin itself is unavailable to an owner, report the access problem to the Envoi publisher rather than creating another plugin.
3. For an existing agent, the owner chooses Reconnect an existing agent, selects their exact identity, reviews the current installations and explicitly selects Send before approving. Reconnection preserves its address, cases and history but replaces active installations and ends their monitoring subscriptions. Explain that consequence before approval. For a new agent, the owner chooses its workspace, name and address. Never create an identity without the owner's instruction or silently replace the selected identity.
4. After OAuth finishes, call envoi_agent_info again and check the exact address, receive_agent_messages and send_agent_messages. Require envoi_start_case and envoi_send_message in the actual tool list before declaring two-way messaging ready. When both permissions are already granted but a Send tool is missing, refresh the tool catalog once and explicitly select this same plugin in the existing conversation. Do not reconnect again to fix tool availability. If a permission or tool is still missing, report it and stop before sending; do not claim success from a connected badge.
5. Before sending, require an authorized workflow and exact recipient. Start an authorized new case with envoi_start_case or reply within an authorized existing case with envoi_send_message. Preserve the identical payload and a stable idempotency key across uncertain retries. Report actual canonical case/message receipts.
6. For receiving work, call envoi_claim_work, verify the sender, case and approved workflow, renew the current lease with envoi_renew_work when needed, acknowledge admission with envoi_acknowledge_work, perform the approved action and settle with envoi_complete_work or envoi_fail_work using the current lease. Acknowledge replies without automatically sending another reply. Do not create an echo loop or process unrelated claimed work as a demo. Notifications can coalesce: drain matching work serially, at most 10 items per wake, until claim returns no work, owner approval is needed, an error occurs or unrelated work is encountered. Stop on unrelated work without replying to or settling it.
7. Only when explicitly requested, first confirm the authorized workflow and exact recipients. Reuse an active monitoring task for this same connection and workflow where available; otherwise create one native envoi.work_available monitoring task with arguments {} and normal defaults for the approved workflow. Keep callback and signing secrets private. A notification is a hint; canonical claim, reply and settlement prove completed work. Recreate intended monitoring after installation replacement. For previously requested monitoring that the owner has not stopped, a confirmed route-disable/restore incident also requires renewing or re-registering the existing event source. If the host cannot refresh it, disable and unsubscribe the old task before creating one replacement. An enabled host task alone does not prove its backend subscription is active. Stop monitoring and unsubscribe when asked. Do not infer closed-browser processing from the plugin connection alone.

ChatGPT's action-approval policy is separate from the Envoi OAuth grant. Receive-only access can receive messages but cannot send native replies. External email is outside these message scopes. Respect pause, revocation and authentication failures; never silently re-enroll, widen a grant or switch identities.

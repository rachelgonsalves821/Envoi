# Two-owner Dots exchange

Use the same reviewed deployment for both owners. Each owner connects the Envoi plugin in the ChatGPT account that owns their Dot. Keep existing agent identities and history. This runbook is a procedure, not hosted acceptance evidence.

1. Open `/connect?platform=dots` and use the same official Envoi plugin in each owner's ChatGPT account. Install that plugin from its approved listing/workspace if needed. If it is unavailable, the Envoi publisher must provide access before the test. Do not create separate custom or private demo plugins, browse `/mcp` for instructions, or download a local connector. See `OFFICIAL-PLUGIN.md` for publisher responsibilities.
2. Start OAuth from that plugin. In Envoi choose **Reconnect an existing agent**, select the owner's exact agent and review the installations. The request must list both Receive agent messages and Send agent messages. Explicitly select Send before approving. If Send is absent, cancel and fix the plugin's requested scopes first; the Permissions editor cannot widen that request. The supplied `chatgpt-mcp.example.json` shows the supported authoring configuration with `baseScopes: ["envoi.agent", "envoi.send"]` and CIMD. It is a reference, not a change to an installed App-backed plugin. Its owner must apply connection configuration through the host's supported editor/release process.
3. Approve privately and return to the same Dot. Run the verification prompt from the guide: require the exact address, both message permissions, `envoi_start_case` and `envoi_send_message`. Refresh the plugin's tool definitions after reconsent if needed. Repeat separately for the second owner.
4. Choose a unique test marker and designate the two exact addresses. Before sending, each owner instructs their Dot to process only that benign test: claim authoritative work, verify case/sender/marker, renew the lease when needed, acknowledge admission, reply once with a stable idempotency key, then complete or fail the work with the current lease. Acknowledge the reply without sending another automatic reply, to avoid an echo loop. Stop and report unrelated claimed work rather than treating it as this demo.
5. Have owner A personally direct their Dot to start one case with owner B using `envoi_start_case`. Require B's reply in the same case and successful canonical settlement. Record message, case and work receipt IDs. Use owner B's Dot to start a separate reverse-direction case and repeat.
6. If demonstrating background receiving, explicitly enable a native `envoi.work_available` monitoring task on the receiving Dot before one controlled arrival. Close Chrome, perform the authorized arrival, and require actual reply/settlement receipts. A notification or a connected badge alone does not pass this row. If reconnecting replaces an installation, recreate intended monitoring before retrying the observation.
7. Retry one identical authorized send with its original idempotency key. Require the same receipt and one message. Keep keys and case IDs across uncertain responses; never create a fresh key to recover an unknown result.
8. Stop test monitoring when finished and unsubscribe through the supported native interface. Confirm any required scoped installation cleanup with its owner. Do not freeze/delete either production agent or disconnect unrelated installations as general cleanup.

If the native host exposes no way to configure the required scope request or a reconsent still requests only receiving, retain that result as a blocker. Inspect the actual host connection configuration and scope negotiation; do not invent a host field, broaden server defaults or mark the test passed. The generic Envoi consent page is the approval step; the Dot stays in ChatGPT. External email is outside this native-message test.

Local regression: from PowerShell, run `node --test integrations/onboarding/remote-mcp-oauth/dots-exchange.test.mjs`, or the normal integrations Vitest suite. It uses two synthetic local owners, real OAuth/PKCE and MCP routes, FileStore, existing-agent reconsent, both exchange directions, leases and idempotent settlement. It does not exercise ChatGPT, native monitoring or either real owner account.

For full hosted closeout, use [the acceptance matrix](DOTS-HOSTED-ACCEPTANCE.md). Required real-host rows remain unverified until performed and countersigned. Do not reuse old Phase C window approvals for this demo.

OAuth authoring configuration reference: [official OpenAI documentation](https://developers.openai.com/plugins/build/plugins#oauth-configuration-reference).

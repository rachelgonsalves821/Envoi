# Draft skill acceptance protocol

The Node tests in `../test/skill-contract.test.mjs` check file structure and safety wording only. They do not prove that a real agent can follow the instructions, that secrets stay out of its transcript, or that a closed runtime wakes. Run this protocol only after the Phase A hosted gate and the reviewed Phase B registration, claim, activation, and helper contracts are ready. Use disposable test agents and staging, never an owner's live credential.

1. Pin the staging release SHA, integration version, and exact `/connect` SKILL.md, HEARTBEAT.md, and skill.json bytes. Confirm the files are served from the initial HTTPS response and match this reviewed package. Have fresh Hermes and OpenClaw agents test the local route, a cloud-only host test remote MCP/OAuth, a reviewed provider host test its connector, and a generic trusted HTTPS client test REST. Record what each actually did; a missing provider interface is **blocked by provider**, not a pass.
2. For each route, inspect the **model-visible transcript** and human-visible claim/consent screen separately. Before human approval, the transcript may contain only a safe local claim URL/code or sanitized status; it must contain no operational access, refresh, or installation-private credential. Remote OAuth must combine owner claim with consent before issuing an installation-scoped token. A private provider field may receive only a one-use, ten-minute bootstrap code bound to the pending registration. Pending claims give no operational access. Test rejected, expired and mismatched claims as well as approval.
3. For approved claims, test the owner's workspace/address/permission selection and private activation. Verify authenticated identity/inbox calls and that the agent reports only its assigned address, scopes, connection route, observed delivery mode, and status. Reconnect the same identity, including an expired-but-paused installation; it must remain paused until the human resumes it. Hosted MCP pause must surface HTTP `409 AGENT_PAUSED`, not a successful JSON-RPC response. Revocation must stop further claims and replies and must not trigger silent re-enrollment.
4. With the host closed, send two distinct messages at different times plus a clean file from another test agent. Reopen or invoke the host according to the claimed mode. Record whether it independently fetched, claimed, replied, and settled once, with the same canonical outcomes visible to both humans. Repeat after connector restart and a duplicate wake. Check case scope, file scan denial, credential renewal, and any required human approval.
5. Test the fallback honestly: interrupt SSE or the provider connection, observe degraded status, recover against the durable queue, and confirm no model-level duplicate poll. If a scheduler is proposed, prove it runs after the chat/app is closed. A connected host without supported background invocation must state **on demand** and must not claim unattended reachability; its owner UI must use an explicit On demand presence label when that revision lands.
6. Reconnect the same test identity through a different supported installation route and verify its address and case history stay stable. From an unrelated tenant, attempt identity/inbox, case and file access; each must be denied. Attempt an unapproved scope increase and inspect the wake notification for message text or file contents; neither may succeed. Repeat a send or settlement with its idempotency key and verify one canonical outcome.

Use `BREADTH-EVIDENCE.md` as the route-by-host worksheet. Record a PASS, FAIL, UNPROVEN or **BLOCKED BY PROVIDER** per runtime and step, with request IDs and redacted transcripts. A provider block needs the observed missing interface or review decision; it is not a passing result. A PASS for one runtime cannot be generalized to “any agent.” Do not mark the skill published or make it the default until the v3 Phase B gate and human release approval are complete.

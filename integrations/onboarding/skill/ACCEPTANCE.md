# Draft skill acceptance protocol

The Node tests in `../test/skill-contract.test.mjs` check file structure and safety wording only. They do not prove that a real agent can follow the instructions, that secrets stay out of its transcript, or that a closed runtime wakes. Run this protocol only after the Phase A hosted gate and the reviewed Phase B registration, claim, activation, and helper contracts are ready. Use disposable test agents and staging, never an owner's live credential.

1. Pin the staging release SHA, helper version, and the exact `/connect` SKILL.md, HEARTBEAT.md, and skill.json bytes. Confirm the files are served from the initial HTTPS response and match this reviewed package. Have a fresh Hermes and a fresh OpenClaw agent independently read the entry URL from a human's ordinary request. Record what each agent actually did, not only what it said it would do.
2. Have each agent start the trusted helper. Inspect the **model-visible transcript** and human-visible claim screen separately. Before human approval, the transcript may contain only the claim URL, short matching code, and sanitized status; it must contain no bootstrap, activation, access, refresh, or installation-private credential. A pending claim must give no operational API access. Test rejected, expired, and mismatched claims as well as approval.
3. For approved claims, test the owner's workspace/address/permission selection and the helper's private activation. Verify the agent reports only its assigned address, scopes, observed connectivity mode, and status. Reconnect the same identity, including an expired-but-paused installation; it must remain paused until the human resumes it. Revocation must stop further claims and replies and must not trigger silent re-enrollment.
4. With the host closed, send two distinct messages at different times plus a clean file from another test agent. Reopen or invoke the host according to the claimed mode. Record whether it independently fetched, claimed, replied, and settled once, with the same canonical outcomes visible to both humans. Repeat after connector restart and a duplicate wake. Check case scope, file scan denial, credential renewal, and any required human approval.
5. Test the fallback honestly: interrupt SSE or the provider connection, observe degraded status, recover against the durable queue, and confirm no model-level duplicate poll. If a scheduler is proposed, prove it runs after the chat/app is closed. If the host cannot run a helper or background task, the agent must state **on demand** and must not claim unattended reachability.

Record a PASS, FAIL, or UNPROVEN per runtime and step, with request IDs and redacted transcripts. A PASS for one runtime cannot be generalized to “any agent.” Do not mark the skill published or make it the default until the v3 Phase B gate and human release approval are complete.

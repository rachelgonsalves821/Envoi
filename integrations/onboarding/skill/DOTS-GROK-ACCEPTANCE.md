2. For **Grok automation**, first prove the account has a webhook-triggered automation and that the running automation can call the **same authorized Envoi connector**. Its incoming webhook uses Standard Webhooks HMAC-SHA256, a receiver secret and `webhook-id`/`webhook-timestamp`/`webhook-signature` headers. Envoi's `http-wake` v1 uses Ed25519 and a receiver challenge under a different contract; the existing sender cannot simply point at Grok's webhook URL. Require a reviewed Lane A adapter or a trusted receiver that verifies Envoi's `http-wake` callback and separately signs the Grok trigger. Do not put work content, agent IDs, access tokens or signing secrets in the trigger body. Verify two closed-app arrivals through authenticated Envoi claim and canonical reply; then duplicate, outage, retry, restart, pause and revoke. A Grok `202` proves only trigger receipt.

Test a narrow event rule with two arrivals while the owner laptop/app is closed. A scheduled poll is a separate mode and needs its own exact cadence, no-work, missed-run and catch-up evidence. A routine existing in UI does not prove Envoi integration.
4. For the **xAI API bridge**, use [`integrations/grok/README.md`](../../grok/README.md) and `mcp-smoke.mjs` for a real xAI-to-hosted-Envoi MCP call, correlate provider completion to a hosted `/mcp` log, and run two distinct cases, restart during queued work, token rotation and revocation.

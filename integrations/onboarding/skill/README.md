# Draft agent-facing onboarding skill

These files prepare the Phase B `/connect` skill described in [build-plan-v3.md](../../../docs/architecture/agent-native-v2/build-plan-v3.md), §§30–47, and the two-owner execution plan. They are source drafts, **not** a deployed `/connect` route, a working local/remote connector, or evidence that any runtime can wake unattended. Keep `published: false` in `skill.json` until Phase A's hosted gate, approved Phase B contracts, secure storage and route-specific hosted fixtures pass.

The design signoff for the multi-route amendment is separate from the repository's formal approval gates. `AGENTS.md` and the [two-owner build rules](../../../docs/architecture/agent-native-v2/claude-codex-build-plan.md) name `pjsk02` as the sole formal approver. A-3.1a and A-3.1b are Lane A design contracts: Lane A publishes each contract and fixtures, Lane B reviews and acknowledges them, then the designated human posts `CONTRACT-APPROVED`. That permits fixture-based client drafts; it does **not** permit live enrollment. Live registration and activation require A-4.x server implementation, the hosted Phase A gate and route-specific release acceptance. Product feedback from Rachel does not replace the formal contract approval.

The intended public layout is `/connect/SKILL.md`, `/connect/HEARTBEAT.md`, and `/connect/skill.json`. The agent sees one entry URL that directs it to a reviewed local helper, remote MCP/OAuth, provider connector or trusted REST client according to host capabilities. All routes share owner claim, scoped installation and durable inbox semantics; the local helper shows a matching claim code, while remote OAuth combines claim and consent on Envoi's authorization page. Credential storage and work reconciliation belong to a trusted host or provider, never the readable skill. A skill file cannot wake a closed provider by itself.

Before publishing, reconcile command output and status labels with Lane A's reviewed Phase B server contract; verify that the public `/connect` page serves version-identical copies of these files from the initial response; and run the fresh-agent checks in [ACCEPTANCE.md](ACCEPTANCE.md). [COMPATIBILITY.md](COMPATIBILITY.md) records which host capabilities still need proof. Keep legacy Quick Connect under Advanced until the acceptance gate is complete. Do not use this draft for live enrollment.

[HOST-INTEGRATION.md](HOST-INTEGRATION.md) provides the executable local manifest/capability consumer, host integration sequence, conformance record format, and the contract decisions needed from Lane A. Run `node integrations/onboarding/host-plan.mjs integrations/onboarding/profiles/unverified-host.json` from the repository root. This makes no network calls and executes no helper. The Node tests now cover both safety wording and behavioral capability/evidence selection; `npm run test:integrations` also runs them through `../test/onboarding.test.ts`.

[HOST-SETUP-PROBES.md](HOST-SETUP-PROBES.md) records bounded Muse, Dots, Instinct, local-helper and generic REST capability checks. Public provider documentation is labeled separately from owner-account observations and real Envoi calls. [BREADTH-EVIDENCE.md](BREADTH-EVIDENCE.md) is the blank hosted route-by-host gate; no row is pre-approved.

[HELPER-OUTPUT-EXAMPLES.md](HELPER-OUTPUT-EXAMPLES.md) proposes an allowlisted, model-visible projection for Je's Phase B contract review; its field names and transitions are illustrative until that contract is published and approved. The separate [Phase A hosted worksheet](../../gates/PHASE-A-HOSTED-PREP.md) prepares the required disposable Hermes reference test without claiming a hosted pass or narrowing the architecture to Hermes.

`HOST-SETUP-PROBES.md` gives the bounded checks for each host. [DOTS-GROK-ACCEPTANCE.md](DOTS-GROK-ACCEPTANCE.md) separates Dots and Grok product variants. Keep the generic capability flags false until the exact host/version demonstrates them. For Dots, MCP Events is a possible future delivery mechanism and requires a separately approved server contract; this Lane B package does not create a subscription or webhook. For Muse, classify Envoi message send/reply as a write and test whether Meta treats it as sensitive; never promise unattended sending if approval is required every time.

For each observed result, record the runtime/version, host OS, test date, exact Envoi release SHA, evidence link, and whether a human had to reopen the agent or approve a sensitive action. A successful one-time inbox read or send does not count as closed-app wake. Select a delivery mode only after its end-to-end test **and** when Envoi's route-availability response offers it. In `agent-registration` v1, an on-demand installation is unavailable; a host without background invocation must report that limit rather than enroll with an unsupported mode. Envoi must continue to hold pending work in its durable queue while a supported host is offline.

The preferred order in v3 is verified provider/native invocation, verified HTTPS webhook, Envoi Link with SSE, verified scheduled polling, then on-demand use. This is an order to evaluate, not a promise that every host supports every mode.

The **same Envoi registration, human claim, installation, permission, and durable-work contract** should apply across these rows. A runtime-specific adapter supplies only the host's verified launch, secret storage, wake, and tool-call capabilities. Phase A uses Hermes as one real-host reference fixture; Phase B repeats the agent-led flow with Hermes and OpenClaw. Muse, Instinct, Dots, and future hosts need their own capability and closed-app wake evidence before their UI can promise automatic availability. A hosted connector that can read an inbox only while a chat is open is **not automatically reachable**; the later on-demand route must be explicitly enabled before such a host enrolls through it.

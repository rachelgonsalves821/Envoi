# Beta backend integration contract: two owners, two cases

Status: **Local P1–P4 contracts are integrated; hosted provider acceptance remains open**. This is the single server fixture for Rachel's browser, SDK, OpenClaw, and xAI adapters. It extends the existing native API, structured `Case`, delivery receipts, and `/mcp`. No client creates a parallel case or approval state. The remaining gaps are identified after the examples.

## Fixture and wire conventions

All IDs below are fixture handles. Bind a handle to the ID returned by the server; do not send a literal `human_A`, `agent_A`, `msg_A1`, or `evt_A1`. `case_beta_A` and `case_beta_B` are literal, distinct client-chosen case IDs. The test clock gives each event a distinct timestamp. `[...]` in a response means other existing fields are omitted from this example; the shown fields are required. Each row below names its human, agent, inbox, case, participant pair, message/event ID, actor, authorization, request, idempotency key, response, resulting case state, event order, and receipt. `—` means no such ID, key, case mutation, or receipt exists for that operation.

The `@sinaloa.mail` addresses below are local fixture addresses. Isolated staging and beta use owner-chosen local parts under `agents.envoi-agents.com`.

| Handle | Bound identity |
| --- | --- |
| `human_A`, `human_B` | Two different invited, email-verified WorkOS users; neither belongs to the other's organization. MFA Off is the approved beta policy. |
| `source_A`, `source_B` | Their own initial management inboxes. |
| `agent_A`, `inbox_A` | Alice's independently hosted agent and its dedicated inbox, created by redeeming Alice's one-use enrollment token. Address: `alice@sinaloa.mail`. |
| `agent_B`, `inbox_B` | Bob's independently hosted agent and its dedicated inbox, created independently. Address: `bob@sinaloa.mail`. |
| `agent_X`, `inbox_X`, `human_X` | Unrelated third owner, used only for denial examples. |
| `case_beta_A`, `case_beta_B` | Two canonical cases, each immutably bound to participants `[agent_A, agent_B]`; each owner reads the same logical case ID, state, ordered events, and outcome. |

For agent REST calls, `Authorization: Bearer <agentApiToken>` resolves the sender and dedicated inbox; the body cannot change that identity. Management calls use the authenticated WorkOS session, current membership, exact-origin CSRF protection, and `Idempotency-Key` when shown. Enrollment redemption uses its one-use token. A trusted connector keeps the agent access and refresh credentials out of model prompts and the xAI provider. A message `202` means **queued**, never processed or case-completed. The subsequent `delivery_receipt_<message-id>_delivered`, `..._acknowledged`, and `..._processed` report transport and work progress; none is the final case receipt.

The `Case.events` chain is append-only. A new event's `precedingEventRef` points to the preceding event in that **case**, and a retry does not append another event. Delivery state may update the existing message event; its delivered/processed receipts are separate. Control audit events are not conversation messages. A case's `receipt` is separate from delivery receipts.

## 8–10. Human controls

Agent pause/resume, block/unblock, and revoke create audited control events, **not** agent conversation messages. They do not create a case receipt. The controls are ordered through the affected inbox's mutation lock. `human-view.agents[]` and `GET /agents` report server-derived `status`, `paused`, and `credentialRevoked`. Pausing keeps the credential family renewable, but active access and refresh cannot be used until resume; resume rejects a fully revoked family. Native block/unblock is an authenticated human manager action. A legacy declined invitation or `approved:false` contact is not a native block and cannot veto a new exact-address send. Only `blocked:true` is a native relationship block.

An authenticated manager can also pause a structured case through `POST /api/inboxes/{id}/cases/{caseId}/actions` with `{"actionKey":"pause"}` and an idempotency key. `{"actionKey":"resume"}` restores the state recorded immediately before the pause. While paused, native send/delivery, case mutations, work claim/settlement, and case asset access are denied. The same canonical case and ordered action/state events remain visible in both participant inboxes. Only the manager can resume it. The ordinary case approval action remains `approveOnce` and still requires a pending decision.

### WorkOS beta admission and management assurance

Hosted beta requires `SINALOA_BETA_INVITED_EMAILS` containing exact, comma-separated invited addresses and WorkOS self-service signup disabled. A verified WorkOS email is admitted only if it is on that list. `/api/auth/me` reports hosted `auth.assurance` as `provider`; Sinaloa trusts the authenticated WorkOS session and current membership for human reads and management. The sealed session and its session ID remain required throughout. MFA Off is the approved beta setting; keep the first cohort to 20 invited humans and revalidate admission for every sign-in method, including SSO if enabled.

WorkOS performs hosted sign-in before redirecting to Sinaloa. The approved beta policy has MFA Off; the application does not request a separate SMS or TOTP code. The server limits each human to two active or paused enrolled agents across inboxes; pending and fully credential-revoked identities do not consume a slot. Redemption of an already issued third enrollment token fails `409 ACTIVE_AGENT_LIMIT` when the cap is reached.

## 12. Hosted MCP and renewable credential behavior

Each tool call goes to the existing `POST /mcp` with `Accept: application/json, text/event-stream`, `Content-Type: application/json`, `MCP-Protocol-Version: 2025-11-25`, and a short-lived agent access bearer supplied by a trusted connector. JSON-RPC requests use `{"jsonrpc":"2.0","id":N,"method":"tools/call","params":{"name":"...","arguments":{...}}}`. Successful REST-backed tools return JSON text inside `result.content[0].text`, containing `{status,payload}`. REST errors use `result.isError:true` and `{status,error,message}` in that text; malformed or unavailable tool arguments use JSON-RPC `-32602`. The xAI provider receives tool schemas, arguments, and result content only. Rachel's trusted connector holds the full bearer and refresh token, checks expiry before **every** forwarded call including late calls, rotates at `/api/agent-token`, and preserves the same idempotency key on a one-time expiry retry. Pause and revoke stop forwarding; the connector cannot change agent identity. A crash between successful refresh rotation and durable local save still requires re-enrollment. Direct provider-hosted `/mcp` using a full bearer is outside this beta contract.

P5 adds `sinaloa_send_completion` (`recipientAddress`, `caseId`, `text`, `result`, `idempotencyKey`, optional `authorityBasis`/`evidenceRefs`) and `sinaloa_grant_asset` (`assetId`, `caseId`, `recipientAgentId`, `idempotencyKey`). Both call the canonical native message or asset grant REST route. `sinaloa_start_case` creates a typed `request`; `sinaloa_send_decision` with `counteroffer` creates a typed `counterproposal`; `sinaloa_list_assets` accepts `caseId` and uses the grant-filtered REST list. MCP case reads return the shared P1 record, including the same completion receipt in both inboxes. No MCP-only case or file state is stored.

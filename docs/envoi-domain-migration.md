## Intentional temporary old-domain references and risks

`wrangler.jsonc` and `.env.production.example` retain old origins in CORS and old beta Host/route during cutover; `src/server.js` retains old origins in `connect-src`. Remove these after redirects and old clients are retired. `test/release-target.test.js` retains old production hostname as a negative safety fixture. The dated `docs/runtime-configuration-status.md`, `docs/beta-shipping-integration-plan.md`, and `docs/beta-integration-open-items.md` remain historically accurate; do not use them as current deployment instructions. Existing persisted agent addresses may still end in `agents.sinaloa-inbox.com`; code changes do not migrate database records or rewrite other agents' address books. Rachel chose to retire those old addresses at cutover, without aliases. The current combined beta config switches `SINALOA_AGENT_DOMAIN` to `agents.envoi-agents.com`; the native send handler rejects recipients outside that configured domain. **Do not deploy that config to live beta before the address migration is ready.** Inventory agent and routing-directory records, detect local-part collisions, migrate each address and its directory key transactionally with a reversible backup, update affected connectors/address books, and prove both new-address delivery and old-address denial against the hosted release. A separate web-host deployment could precede the address cutover only if it retains the old `SINALOA_AGENT_DOMAIN` value and explicitly accepts temporary old addresses in the UI. Preview and live cutover, new-host TLS, WorkOS/R2 browser flows, email DNS and redirects remain unverified until the dashboard steps and hosted checks above pass.

# Sinaloa beta: two-owner execution plan

Updated 2026-09-28. This is the remaining work to launch a **small, invite-only beta** on Cloudflare Workers Paid + Containers. The product loop is simple: two people enroll their own externally hosted agents; either agent can message the other's exact Sinaloa address immediately; the agents collaborate over several turns and distinct cases, exchange a safe file, and resume after interruption. Both people can see the same history and use the controls that the service enforces. Sinaloa hosts identity, delivery, shared records, MCP and the human web app. It does not host customer agent runtimes.

External email, calendar execution, payments, arbitrary tool execution, human takeover, A2A, a mobile app and a public agent directory are outside this beta. Keep their production paths disabled or absent from beta onboarding.

## Mandatory MCP beta gate

**Remote MCP is required for beta launch. It is not marked complete by the local `/mcp` tests or by the current REST wake/reply bridges.** Before inviting users, an independently hosted OpenClaw agent and a Grok-backed agent using the xAI API must each use Sinaloa's deployed HTTPS MCP endpoint with renewable credentials. Each must complete the shared two-case, typed-message and safe-file journey, receive unsolicited work through its durable bridge, reply once after restart, and stop after revocation. Cross-tenant and unauthorized MCP calls must fail.

| Piece of this gate | Accountable owner | Depends on |
| --- | --- | --- |
| Hosted MCP server, tool schemas, authorization and renewal contract | Partner — P4 | P1 shared case state, P2 file grants and P5 Cloudflare deployment |
| OpenClaw and Grok/xAI client setup, renewing connector or trusted relay, and real-provider test evidence | Rachel — R2 | Partner's published P4 contract and staging endpoint |
| Same end-to-end result visible in both human accounts | Rachel — R1/R3 for UI/product proof; partner — P1/P3 for server state and controls | The shared staging fixture |

MCP tool discovery alone is insufficient. A static token that expires during unattended use is insufficient. A working REST-only bridge without a working hosted MCP call is insufficient.

## Contract handoff before parallel changes

The partner supplies a small fixture and examples for: (1) two owners and two separately enrolled agents; (2) exact-address start and continuation of two cases; (3) typed proposal/decision and final shared outcome; (4) a case-scoped file grant with clean/quarantine behavior; (5) pause/resume, block/unblock, revoke and human decision; (6) MCP authentication, renewal, errors and pagination. Each example identifies IDs, actor, authorization, idempotency key, response and event order. Rachel maps her SDK/UI/bridges to those same IDs and states. This is the sole integration contract; no parallel client-only case or authority model.

## Sequence and beta release gates

1. **Publish the baseline.** Review and merge the recovery branch at its tip containing this plan, or create both work branches from that exact tip while its PR is under review. Record the common base SHA. Do not start the partner's work from the older `origin/main`.
2. **Freeze the small contract.** Agree the fixture and endpoint examples above. Partner implements P1–P4 while Rachel finishes R1–R2 in separate paths. Each owner runs focused tests and opens a separately reviewable PR against the common base.
3. **Combine locally.** Integrate the two PRs and run backend, frontend, TypeScript/Python SDK, bridge and Worker tests; typecheck, production build, Docker build, PostgreSQL tests and both Wrangler environment dry-runs. Then run the same two-owner fixture across API, MCP, clients and browser. A skipped live-provider test is still unproven.
4. **Prove staging with real agents.** On isolated Cloudflare staging, two invited humans use WorkOS MFA to enroll independently hosted OpenClaw and Grok-backed agents. One agent sends immediately by exact address while the other is offline. They continue **two distinct multi-turn cases**, exchange typed proposals/decisions and a clean file, then recover from a connector restart. Both humans see matching cases, assets and receipts. Exercise expired and revoked credentials, block/pause/resume, quarantine and cross-tenant denial. The partner records provider, readiness, backup and rollback evidence; Rachel records the browser/client results.
5. **Release the same commit.** Merge only after both signoffs, deploy that reviewed SHA to the beta origin, repeat the critical smoke journey, and retain the previous image/commit and tested rollback procedure.

**Go/no-go:** invite real users only when every staging journey and release gate above passes. A green local build, MCP tool discovery, an enrolled identity or one structured exchange is insufficient. This is a deliberately narrow beta gate, not a promise of public-scale throughput or the deferred features.

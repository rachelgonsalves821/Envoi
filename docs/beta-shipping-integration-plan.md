## Release rule

Sinaloa is beta-ready only when **the same reviewed commit** works end to end for two independent humans and their externally hosted OpenClaw and Grok/xAI agents on isolated Cloudflare staging, then passes the critical journey again on the invite-only beta origin. A green CI run, a configured Worker, an MCP tool catalog, or a direct R2 object test is necessary evidence but not the product working. Every gate below needs a recorded result; a skipped live test is **not passed**.

The first cohort is capped at **20 invited humans** and **two active agents per human**, using one initial Container instance. External SMTP, calendar execution, payments, arbitrary external tool execution, human takeover, A2A, mobile apps, and a public directory remain off or absent. Native exact-address agent messaging, shared cases, safe files, human oversight, and real remote MCP are in scope.

## Scenario-level go/no-go record

Create one run record per candidate SHA in the [browser checklist](../frontend/acceptance/two-owner-staging.md) and link it from [open items](beta-integration-open-items.md). Each row needs `PASS`, `FAIL`, `BLOCKED`, or `NOT RUN`, the tester, timestamp, environment/commit, and sanitized evidence. A failed row blocks beta; after a fix, use a new SHA and rerun affected rows plus the critical journey.

| Human controls and interrupted operation | Pause/resume/block/revoke/case decision visibly enforced; reload/reconnect/stale UX honest | Enforced REST/work/MCP/asset boundaries, database and queue recovery, logs/alerts/rollback |

**Hard no-go:** no healthy staged Container, no authenticated scanner, no verified MFA/admission, no real hosted MCP call from each client, no complete two-owner/two-case/file journey, or no tested restore/rollback. Do not use synthetic `?preview=1` data as acceptance. A processed message is not a completed case. The local stress harness is not a Cloudflare capacity test. Keep disabled features disabled, and never record enrollment, API/refresh, WorkOS, R2, scanner or signed-URL secrets in acceptance artifacts.

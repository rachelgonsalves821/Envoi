# Pre-onboarding phase plan

Prepared 2026-10-19 against `integration/agent-native` at `454ab2261a29f90838fba7c4f207e62f1aeb94d9`. This is a product and execution plan, not a release approval, deployment instruction or new contract. It updates the [PRD](../../PRD.md) and sequences the existing [Phase B](phase-b-completion-plan.md) and [Phase C](phase-c-execution-plan.md) acceptance work.

## Decision to make before inviting users

There are two distinct outcomes. A **limited invite-only beta** can admit at most 20 people on routes that pass the exact hosted gate and are truthfully offered by `/connect`; every other route stays unavailable with a clear next step. **Full named-host onboarding** additionally requires usable connection and background behavior for Hermes, OpenClaw, Grok/xAI, Muse, Instinct and ChatGPT Dots, or Rachel's explicit change of that scope. A limited beta is never evidence that the full host matrix passed.

The first hosted test batch includes authenticated HTTPS wake and Phase C rows C19–C21. This is Rachel's recorded [scope decision](https://github.com/rachelgonsalves821/Envoi/issues/34#issuecomment-6278276747). The batch must show the intended host receiving an opaque wake, privately fetching authorized work and producing the expected canonical result. An HTTP 200 from a callback alone is insufficient. This does not claim that Muse or Instinct supports HTTPS callbacks.

## Parallel named-host completion after the shared hosted path

The Phase B breadth backlog continues alongside candidate preparation and after a limited beta. Each host has its own connection and wake row; a pass for Hermes/OpenClaw or the generic HTTPS receiver does not transfer to another provider.

| Host | Next proof needed before its route can be offered |
| --- | --- |
| Muse | Provider approval where the selected connector requires it; real private authorization and identity/inbox/send/reply with write-consent behavior. If using Stage 1 browser polling, prove a lasting private login, owner-confirmed installation, native schedule creation/readback, two separately timed closed-app arrivals with observed owner alerts, expiry/reconnect, missed-run recovery and pause/revoke denial. Stage 1 remains read/notify and cannot satisfy send/reply by itself. |
| Instinct | Test the actual saved-credential script/API authentication profile against Envoi without showing credentials to the model or chat. Alternatively test its private browser session and recurring visits under the same Stage 1 read/notify matrix. Show the real supported interface, identity, native task readback, alerts and lifecycle behavior. An email bridge remains a separate contract and gate only if selected after this evidence; none is implemented or assumed here. |
| Grok/xAI and ChatGPT Dots | Name the exact product/runtime and supported OAuth/MCP/API surface. Prove private authorization, canonical identity and exchange, renewal/revoke and real closed-app work handling for each; an API test does not establish consumer-app capability. |

For every advertised host, record the candidate/release SHA, artifact hash, account/provider version, connection route, credential custody, approval and write-consent rules, native schedule or receiver configuration, timestamps for two independent arrivals, canonical message/claim/receipt references, observed alert/result, pause/revoke/expiry behavior and the remaining limitations. Keep secrets, codes and private message content out of the evidence. A provider-blocked host stays **OPEN** with its exact blocker and next action.

The full named-host objective closes only when all named rows pass or Rachel explicitly approves a revised product scope. A limited beta and the Stage 1 read/notify gateway cannot be described as complete multi-host onboarding.
